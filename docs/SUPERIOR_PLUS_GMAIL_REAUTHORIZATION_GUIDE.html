What failed?

The website’s content, form and recipient address are intact. Google rejected the website’s saved authorisation token:

invalid_grant
Token has been expired or revoked.

WordPress therefore reached the email-sending stage but WP Mail SMTP could not obtain permission from Google to send the message.

Before beginning

  • Have a WordPress Administrator account available.
  • Have access to sppainting.remodeling@gmail.com.
  • Keep the existing Google OAuth Client ID and Client Secret.
  • Use the Google Cloud project originally created for the website mail connection.
  • Never send passwords, Client Secrets, recovery codes or access tokens by email or chat.
Step 1 · Google Cloud

Prevent another seven-day expiry

Before reconnecting WordPress, confirm that the Google OAuth application is not left in Testing mode.

1

Sign into Google Cloud Console using sppainting.remodeling@gmail.com.

2

Use the project selector at the top and select the project created for website email, commonly named Superior Plus Website Mail.

3

Open Google Auth Platform → Audience. In an older Google interface this may appear under APIs & Services → OAuth consent screen.

4

Find Publishing status.

5

If the status is Testing, choose Publish App or In production and confirm.

6

If it already says In production, leave it unchanged and continue to the next page.

Why this matters: for an External OAuth app requesting Gmail permissions, Google normally expires refresh tokens after seven days while the app remains in Testing. Reconnecting without publishing can make the same failure return.

Do not change these items

  • Do not delete the Google Cloud project.
  • Do not delete the existing OAuth Client ID.
  • Do not create a second project unless the original project is genuinely inaccessible.
  • Do not change the authorised redirect URI unless WP Mail SMTP reports a redirect mismatch.
Step 2 · WordPress

Remove the expired connection

1

Sign into the WordPress dashboard as an Administrator.

2

Open WP Mail SMTP → Settings → General.

3

Scroll to the Google / Gmail mailer section.

4

Confirm the existing Client ID and Client Secret fields are populated. Do not copy or share their values.

5

Click Remove OAuth Connection and confirm the removal.

6

Save the WP Mail SMTP settings if the page requests it.

Safe operation: removing the OAuth connection does not delete Gmail messages, WordPress enquiries, website content, the Client ID or the Client Secret. It removes only the expired access authorisation.

Step 3 · Reauthorise

Allow WordPress to send again

1

On the WP Mail SMTP settings page, click Allow plugin to send emails using your Google account.

2

When Google opens, select sppainting.remodeling@gmail.com. Do not authorise a developer’s or another employee’s account.

3

Review the project/app name and requested Gmail permission.

4

Click Allow or Continue.

5

Wait for Google to return to the WordPress dashboard.

6

Confirm WP Mail SMTP displays a successful connection for sppainting.remodeling@gmail.com.

If Google displays an unverified-app warning: continue only when the client recognises the exact private project created for this website. Never proceed when the project name, account or domain is unfamiliar.

If authorisation is denied

Step 4 · Verification

Test email and the website form

Test A — WP Mail SMTP

  1. Open WP Mail SMTP → Tools → Email Test.
  2. Send a test to an inbox that can be checked immediately.
  3. Confirm the WP Mail SMTP result is successful.
  4. Confirm the message actually arrives in Inbox, Spam or All Mail.

Test B — Live website quote

  1. Open the live Contact page in a private/incognito window.
  2. Complete every required field with controlled test details.
  3. Enter NEW FORM TEST — PLEASE IGNORE in Project Details.
  4. Submit the form and confirm the success screen appears.
  5. Confirm the enquiry reaches sppainting.remodeling@gmail.com.
  6. Press Reply and verify the reply is addressed to the customer email entered in the form.

Test C — Superior Plus status

  1. Return to WordPress Dashboard → Superior Plus.
  2. Under Quote form delivery, confirm the recipient is correct.
  3. Confirm Last confirmed delivery updates to the new test time.
  4. Confirm no newer Last mail failure appears.
Successful outcome: the SMTP test arrives, the website displays its success message, the quote reaches the business inbox, and the Superior Plus delivery timestamp updates.
Important distinction

Older admin@admin.com failures

Gmail may continue displaying delivery-failure notices for older messages that were previously addressed to admin@admin.com. Reauthorising Gmail cannot rewrite or cancel messages already queued by Google.

Judge only new tests. Compare the original message time and destination. A retry for an old message does not mean the newly repaired form used the old recipient.

Check remaining WordPress addresses

  • Superior Plus → Quote form delivery: recipient is sppainting.remodeling@gmail.com.
  • Settings → General: Administration Email Address is valid and has no pending confirmation.
  • Users → All Users: no Administrator user has admin@admin.com as their account email.
  • WP Mail SMTP → Settings: From Email is the authorised Gmail address.

When to request help

Save a screenshot of the complete WP Mail SMTP error and record:

  • The date and time of the test
  • Whether the error occurred during Google authorisation, Email Test or website-form submission
  • The error code and description

Do not include the Client Secret, access token, refresh token, password or recovery codes in screenshots.

Final checklist

Connection handoff

  • Correct Google Cloud project selected.
  • OAuth publishing status changed from Testing to In production, if applicable.
  • Existing Client ID and Client Secret retained.
  • Expired OAuth connection removed.
  • sppainting.remodeling@gmail.com reauthorised.
  • WP Mail SMTP Email Test delivered.
  • New live website quote delivered.
  • Superior Plus delivery timestamp updated.
  • No administrator account uses admin@admin.com.
No theme or Superior Plus plugin update is required. The failure is an expired external Google authorisation, and the repair is completed in Google Cloud and WP Mail SMTP.
