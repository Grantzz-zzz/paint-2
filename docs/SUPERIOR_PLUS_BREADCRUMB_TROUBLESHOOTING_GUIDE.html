Read this first

What the warning means

Google reported the breadcrumb error:

Either name or item.name should be specified in itemListElement.

A breadcrumb trail tells Google where a page belongs in the website hierarchy, for example:

Home > Services > Residential Painting

Each breadcrumb entry is a ListItem. Google expects a position and a readable name. A blank page title, malformed schema, old cached script, or competing schema generator can leave one entry without that name.

Important: an email alert is not a live diagnosis

Search Console reports what Google found during an earlier crawl. The live website may already be fixed while the report still shows the old error. Always identify the exact affected URL and run a live test before changing settings.

Current site-specific fix: Superior Plus theme 3.6.2 creates both a named breadcrumb ListItem and a named linked WebPage. This guards against empty or incomplete breadcrumb names.

Phase 1

Identify the exact affected URL

1

Sign in to the correct Google Search Console property for https://sppaintingremodeling.com.au/.

2

Open Enhancements > Breadcrumbs. Depending on the Search Console layout, Breadcrumbs may appear beneath Shopping and enhancements.

3

Open the issue named Either 'name' or 'item.name' should be specified.

4

Scroll to Examples or Why items are invalid. Copy every example URL into a document.

5

Click one example, then choose the inspect or magnifying-glass option to open URL Inspection.

Do not troubleshoot only from the email screenshot. The email states the error type but usually does not identify the page. The affected URL inside Search Console determines the correct remedy.

Site-specific legacy URL to recognise

A malformed page previously used a path similar to:

https://sppaintingremodeling.com.au/https-sppaintingremodeling-com-au/

If this appears in the examples, do not restore it as another homepage. Keep it removed and treat it as an obsolete URL using the decision process later in this guide.

Phase 2

Install the verified website correction

The breadcrumb fix is part of the WordPress theme because the React frontend produces the site's breadcrumb structured data. The companion content plugin contains the matching editor update.

Before updating

  • Create a full hosting backup of files and the WordPress database.
  • Confirm that an administrator can restore the backup.
  • Use a staging copy first when hosting provides staging.
  • Do not delete current theme or plugin data before uploading replacements.

Upload the plugin

  1. Open WordPress Dashboard > Plugins > Add Plugin > Upload Plugin.
  2. Select superior-plus-content-2.7.1.zip.
  3. Click Install Now.
  4. When WordPress detects the existing plugin, choose Replace current with uploaded.
  5. Confirm that Superior Plus Content remains active.

Upload the theme

  1. Open Appearance > Themes > Add New Theme > Upload Theme.
  2. Select superior-plus-3.6.2.zip.
  3. Click Install Now, then Replace current with uploaded.
  4. Confirm that Superior Plus Painting is still the active theme.
Do not activate a generic WordPress theme to test this. The live design and structured-data implementation are delivered by the Superior Plus theme.

Basic post-update check

  • Homepage loads with the intended edited content.
  • Services, Areas, About, Our Process, FAQs, Blog and Contact open normally.
  • A service detail page displays Home / Services / Page name.
  • No page shows a blank screen or persistent loading screen.
Phase 3

Clear every cache layer

A correct theme can still appear incorrect when a cache serves an older JavaScript bundle or older HTML. Clear caches from the inside out.

LayerAction
WordPress cache pluginUse Purge All, Clear Cache, or the equivalent command.
Optimization/minification pluginClear generated CSS/JS. Temporarily disable JavaScript delay or combination only if the live test still receives old markup.
Hosting/server cacheUse the host dashboard's purge or flush command.
CDN or CloudflarePurge the affected URLs or purge the cache. Avoid changing DNS or security settings.
BrowserUse a private/incognito window or hard refresh. Browser cache does not control Google, but it confirms what visitors receive.

Confirm the new frontend is being served

  1. Open an affected URL in a private browser.
  2. Refresh it twice.
  3. Confirm the visible breadcrumb uses readable text and the correct page hierarchy.
  4. If the page still shows the old behavior, repeat the hosting/CDN purge before changing WordPress content.
Why cache matters: Googlebot fetches the publicly served page. If a CDN still serves the older theme bundle, Google can continue seeing the old breadcrumb even though WordPress shows the new version in the dashboard.

What not to purge or reset

  • Do not reset the Superior Plus Content plugin.
  • Do not restore original page content merely to repair schema.
  • Do not delete service records, locations, images, or edited text.
  • Do not change permalinks unless a separate permalink problem has been confirmed.
Phase 4

Test the live structured data

A. Google Rich Results Test

  1. Open https://search.google.com/test/rich-results.
  2. Choose the URL test.
  3. Paste the exact affected URL from Search Console.
  4. Run the test and open the detected Breadcrumbs result.
  5. Expand every breadcrumb item. Confirm each item has a readable name and sequential position.
  6. Repeat on the homepage, Services directory, one service page, one area page and one blog article.

B. Search Console live URL test

  1. Return to Search Console and paste the full affected URL into the top inspection bar.
  2. First note the result under Google Index. This is Google's stored version.
  3. Click Test live URL. This fetches the current website.
  4. Open View tested page or enhancement details and verify that Breadcrumbs no longer show the error.
  5. If the live test passes but the indexed result fails, the website is fixed and Google has not recrawled it yet.

Indexed fails / Live passes

Usually a stale Google copy. Request indexing, then validate the fix. Do not keep changing the site.

Indexed and Live both fail

A current page, cache, plugin, or schema-source issue remains. Follow the diagnostic branches on the next pages.

Expected processing time: Google's validation may take about two weeks and sometimes longer. A pending report does not mean the update failed.

Yoast and plugin conflicts

How to handle multiple breadcrumb systems

Yoast SEO can generate breadcrumb JSON-LD when its breadcrumb feature, block, shortcode, or theme integration is used. The Superior Plus theme also generates the website's breadcrumb trail. Multiple valid trails are not automatically an error, but a single malformed trail can keep the whole issue active.

Preferred configuration for this website

Use the Superior Plus theme as the breadcrumb authority. It matches the React routes and now includes defensive names in theme 3.6.2. Yoast may continue handling SEO titles, descriptions, canonical settings and sitemaps.

Check Yoast without deleting SEO work

  1. Open Yoast SEO > Settings > Advanced > Breadcrumbs.
  2. Check whether theme breadcrumbs are enabled.
  3. Edit the affected WordPress page and check for a Yoast Breadcrumbs block or [wpseo_breadcrumb] shortcode.
  4. Check whether another breadcrumb or schema plugin is active under Plugins.
  5. If the Rich Results Test identifies an invalid duplicate, disable or remove only that duplicate breadcrumb output.
  6. Purge caches and run the live test again.

Do not remove these merely because Yoast is installed

  • SEO titles and meta descriptions
  • XML sitemap functionality
  • Canonical URLs that correctly point to the same live page
  • Organization or WebSite schema that does not duplicate a broken breadcrumb
If disabling Yoast breadcrumbs removes the visible trail: restore the setting and obtain technical support before proceeding. The visual breadcrumb and JSON-LD need to remain coordinated.
If the page source has only one BreadcrumbList and it is valid: stop changing plugins. The remaining Search Console report is likely historical or crawl-related.
Old URLs and redirects

What to do when the affected page no longer exists

An obsolete URL does not need breadcrumb markup. The goal is to make its status unambiguous and prevent it from returning a thin or fake page.

Choose the correct response

SituationCorrect handling
The old URL has a direct, equivalent replacement.Use one permanent redirect to the replacement.
The URL was accidental and has no equivalent page.Leave it unavailable with a real 404 or 410 response. Remove it from menus and sitemap.
The page is in WordPress Trash.Do not republish it. Confirm the public URL no longer returns a content page.
The old URL redirects to the homepage only because it is missing.Avoid blanket homepage redirects. They can be interpreted as soft 404s.

Verify the obsolete URL

  1. Open it in a private browser.
  2. Confirm whether it displays a true replacement, a real not-found page, or an unintended fake homepage.
  3. Search the WordPress Pages list, including Trash, for its slug.
  4. Check the sitemap and navigation for references to it.
  5. Inspect the URL in Search Console and run Test live URL.
How Google closes the breadcrumb issue: if Google recrawls the URL and the invalid breadcrumb is gone, the instance can pass. That can occur because valid markup replaced it or because the obsolete page is no longer available.
Final validation

Submit the repair to Google

Only start validation after representative live URLs pass. Starting too early can cause an immediate failed validation.

Pre-validation checklist

  • Theme 3.6.2 is active.
  • All website and CDN caches were cleared.
  • The exact affected URL was identified.
  • Rich Results Test detects valid Breadcrumbs or correctly finds none on an obsolete URL.
  • Search Console Test live URL no longer reports the breadcrumb error.
  • No invalid duplicate BreadcrumbList remains.
  • The page is accessible and indexable if it is intended to appear in Google.

Validation steps

  1. Open Search Console > Breadcrumbs.
  2. Open the exact error.
  3. Click Validate fix.
  4. Record the start date and do not repeatedly restart the process.
  5. Monitor the states Started, Looking good, Passed or Failed.
  6. If validation fails, open See details, copy the failed URL, and diagnose that URL specifically.
Live test passing is the main technical confirmation. Search Console's historical report can remain visible until Google recrawls enough affected URLs.

Recommended sample after deployment

  • https://sppaintingremodeling.com.au/
  • https://sppaintingremodeling.com.au/services/
  • One residential or commercial service detail URL
  • https://sppaintingremodeling.com.au/additional-services/
  • One service-area URL and one blog article URL
Escalation pack

What to collect if the problem remains

Send the following evidence to the website developer or hosting provider. This avoids guesswork and repeated changes.

  • Screenshot of the Breadcrumb issue details and affected URL list.
  • Exact URL that fails the live test.
  • Screenshot of indexed result and live result.
  • Rich Results Test share link or screenshot with the failing breadcrumb expanded.
  • WordPress theme version and Superior Plus Content plugin version.
  • List of active SEO, schema, cache and optimization plugins.
  • Confirmation of which WordPress, host and CDN caches were cleared.
  • Whether the URL is published, redirected, trashed, noindex or 404.
  • User-declared and Google-selected canonical URLs.
  • Date and time of the most recent live test.

Do not send

  • WordPress passwords, Google passwords or hosting passwords by email or chat.
  • OAuth tokens, recovery codes, API secrets or full backup archives.
  • Unredacted personal customer enquiries.

Official guidance and quick decision tree

Quick decision tree

1. Can you see an affected URL in Search Console?
If no, open the Breadcrumb issue and its examples. Do not change the website from the email alone.
2. Does Test live URL pass?
If yes, request indexing and validate the fix. If no, continue.
3. Is it a real current page?
If yes, update/cache-test/schema-test it. If no, keep it removed or redirect it only to a genuine equivalent.
4. Are multiple BreadcrumbList objects present?
If yes, identify which one is invalid and disable only that breadcrumb source.
5. Does the Rich Results Test pass after caches are purged?
If yes, validate. If no, send the escalation pack to technical support.
